# AGENTS.md

- Tenant isolation: every business table has `business_id` + RLS via `is_member()` / `has_biz_role()` — never query without it.
- Roles live in `business_members.role` (per business), not on user profiles — prevents privilege escalation.
- Multi-step financial/stock operations must be Postgres functions (RPC) so they commit atomically.
- Money columns are `numeric(14,2)`; never use floats for amounts.
- Audit logging is via the `audit_row()` trigger on each business table — add the trigger to every new business table.
- App pages live under `src/routes/_authenticated/app/`; the layout resolves the current business in `beforeLoad`.
- Master CRUD uses `EntityManager`, tenant-scoped writes and related-query refresh for consistency.
- UI permission checks in `lib/business.tsx` are hints only; database policies are the source of truth.
- Product SKUs are generated by the tenant-scoped `product_variants_auto_sku` database trigger when omitted, preventing concurrent duplicates.
- Posted money/expense/journal entries are never edited in place: cancel = opposite entry (reversed_at/reversal_of), edit = reverse + re-create — keeps an audit trail.
- Backup/restore/reset run as owner-only RPCs; the `app.bulk` setting skips audit/opening/seed triggers during bulk wipes and restores.
- Global keyboard shortcuts and Enter-to-next-field live in `lib/shortcuts.ts` (one window listener in the app layout); barcode/QR scanning goes through `components/erp/ScanButton` so every search box scans the same way.
- Owner Guardian checks are rule-based SQL in `_guardian_run` (pg_cron hourly + "Check now" RPC); alerts are deduped by fingerprint and auto-close when the problem disappears — only low-risk fixes (mobile format) run automatically.
- Guardian owner pages share a tenant-scoped database snapshot with deterministic reconciliation; AI only advises from that snapshot so generated text never becomes accounting truth.
- Guardian chat uses AI SDK UI-message streaming with server-validated business roles; browser speech input remains editable before submission to avoid unintended commands.
- Company context lives on the existing business record and is owner-editable through an authenticated server function to keep identity and backup ownership unified.
- Visible app queries refresh periodically as well as after writes and window focus; this reconciles cross-device reads without claiming instantaneous realtime delivery.
- Warranty replacement cannot close by status alone until replacement IMEI, stock and financial postings are linked atomically; prevents unrecorded inventory loss.

- Homepage entry intent persists in same-origin session storage across login/OAuth and is consumed by the app layout, so House & Stock opens the shared command palette without duplicating it.
- Brand-shop accounting uses existing tenant-scoped branches and posted transactions, not separate financial tables, to preserve one stock and accounting source of truth.
- Shop reports aggregate decimal amounts in one authenticated database snapshot with explicit business, branch and date scopes; prevents pagination truncation and mixed-time totals.
- Public site identity projects only the deployment company's name into a separately permissioned table synchronized from its business record; login branding never exposes private company fields.
- Visible company identity comes from the current business record and refreshed public branding query, while legacy backup format identifiers remain unchanged for compatibility.
- Daily owner summaries come from the tenant-scoped `daily_summary` RPC, split into dealer house (head/warehouse) and brand shops (branch) in `lib/daily-summary.ts`, so the on-screen summary, shared text and emails use the same numbers.
- Daily report emails go through the Resend connector from one server helper (`daily-report.server.ts`), triggered by Day close and a midnight-Dhaka pg_cron callback authenticated with a database-held job token; Resend idempotency keys prevent duplicate sends.
- Offline mode: last-loaded data persists in IndexedDB; database writes made offline are queued at the fetch layer (`lib/offline-queue.ts`) and replayed through the same RPC/RLS paths on reconnect, so the server stays the only judge of stock/IMEI/balance conflicts. The service worker registers only via `lib/pwa.ts` (never in dev/preview).
- Offline sync history is device-local (IndexedDB, `nextHistory` in `lib/offline-queue.ts`) because queued entries never reach the server until replayed.
- In-app usage logging writes `page_visits` (owner/manager readable) from `VisitLogger` only while online, so tracking never enters the offline write queue.
- Mobile bottom navigation lives in the authenticated app shell and opens the existing sidebar for all menus; shared safe-area spacing keeps content and offline status above it without duplicating navigation state.
- Shops/houses are tenant `branches`; `brand_shop_report` accepts any location. Accounts and branch maintenance share a branch search parameter to preserve selection.
